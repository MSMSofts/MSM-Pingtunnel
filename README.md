# Pingtunnel Manager 2.5 — رمزنگاری خودکار، یک سرور ایران + یک سرور خارج

مدیر سبک و یکپارچهٔ [Pingtunnel](https://github.com/esrrhs/pingtunnel) برای **فقط دو VPS**: ایران نقش `Client` دارد و خارج نقش `Server`. هسته تونل همچنان **Go** است؛ Rust فقط برای منو و مدیریت systemd استفاده می‌شود. ترافیک بین دو سرور از ICMP عبور می‌کند.

**HA و سرور پشتیبان، Multi-Endpoint، انتخاب مسیر خودکار و قابلیت‌های وابسته به آن از این نسخه حذف شده‌اند.** برای پایداری، `systemd` در صورت توقف غیرمنتظره هسته Go آن را دوباره راه‌اندازی می‌کند. در این معماری مسیر جایگزین نداریم و قطع شبکه لزوماً بدون وقفه قابل جبران نیست.

## نصب یک‌خطی (روی هر دو VPS)

```bash
curl -fsSL https://raw.githubusercontent.com/meysamrn/Pingtunnel_manager/main/Source/install.sh -o /tmp/pingtunnel-install.sh && sudo bash /tmp/pingtunnel-install.sh
```

پیش‌نیاز: Ubuntu/Debian دارای systemd، دسترسی sudo/root و امکان دانلود فایل‌ها از GitHub. فایل نصب را می‌توان [پیش از اجرا بررسی کرد](Source/install.sh).

پس از نصب، **فقط** دستور زیر را اجرا کن:

```bash
pingtunnel
```

منو از کاربر عادی در صورت نیاز دسترسی sudo می‌گیرد. برای بار اول گزینهٔ **6 — Easy setup** را انتخاب کن.

## راه‌اندازی اولین بار

**در VPS خارج:** از منو `Easy setup` و سپس `1) Foreign Server` را انتخاب کن. برنامه یک کلید عددی جدید تصادفی تولید می‌کند. کلید را به‌صورت امن به سرور ایران منتقل کن.

**در VPS ایران:** `Easy setup` و سپس `2) Iran Client` را انتخاب کن. فقط آدرس IP/DNS سرور خارج، کلید تولیدشده و مقصد واقعی سرویس در سمت خارج، یعنی `host:port` را وارد کن. آدرس مقصد باید حقیقتاً روی سمت خارج دسترس‌پذیر باشد.

به‌طور پیش‌فرض پورت محلی ایران برای **TCP برابر 443** و برای **UDP برابر 444** است. تغییر پروتکل از منو، فقط وقتی پورت قبلی همان پورت پیش‌فرض باشد آن را به پیش‌فرض جدید تغییر می‌دهد؛ **پورت‌های سفارشی و تنظیمات نصب‌های قبلی دست‌نخورده می‌مانند**. **انتخاب UDP فقط مربوط به ترافیک منتقل‌شده است؛ خود تونل همچنان ICMP است.**

به‌جز این اطلاعات ضروری، نصب وابستگی‌ها، آماده‌سازی سرویس، اجرای خودکار هنگام بوت، ذخیره تغییرات و بازیابی پس از توقف پردازش با سیستم انجام می‌شود. برنامه نمی‌تواند IP سرور دیگر، کلید ازپیش‌مشترک یا مقصد واقعی را بدون اطلاع کاربر حدس بزند.

## رمزنگاری خودکار AES-256-GCM و XChaCha20-Poly1305

هسته Go در هر VPS، هنگام شروع، سرعت واقعی رمزگذاری و بازکردن بسته‌ها را با هر دو الگوریتم اندازه‌گیری و **برای ارسال** سریع‌تر را انتخاب می‌کند. برای **دریافت** هر دو الگوریتم را می‌پذیرد؛ بنابراین دو سرور می‌توانند انتخاب‌های متفاوتی داشته باشند. نوع الگوریتم و مشخصات بسته با AEAD احراز اصالت می‌شود. هیچ تنظیم دستی برای انتخاب الگوریتم وجود ندارد.

سرور خارج در Easy setup یک کلید مستقل تصادفی ۲۵۶ بیتی تولید می‌کند. این کلید در Easy setup سرور ایران یک‌بار با ورودی مخفی وارد می‌شود. کلیدهای مستقل AES و XChaCha از کلید اصلی با HKDF مشتق می‌شوند. کلید در فایل با مجوز 0600 است و در آرگومان‌های Go نمایش داده نمی‌شود.

**برای ارتقا:** نخست نرم‌افزار را روی هر دو VPS به نسخه 2.5 ارتقا بده. سپس روی سرور خارج `pingtunnel` → Easy setup را باز و کلید تولیدشده را بردار. بعد در Easy setup سمت ایران همان کلید را وارد کن. نصب‌کننده برای کانفیگ‌های قدیمی بدون کلید جدید، به‌طور خودسرانه کلید ناسازگار نمی‌سازد؛ تا زمان فعال‌سازی هماهنگ، نصب قدیمی ممکن است بدون رمزگذاری جدید کار کند. این فعال‌سازی اولیه می‌تواند باعث وقفه کوتاه شود.

هسته همچنان Go است. GitHub Actions نسخه مشخصی از `esrrhs/pingtunnel` را دریافت و فایل‌های `Go/crypto.go`، `Go/auto_crypto.go` و تست‌های رمزنگاری را اضافه می‌کند. Go core تغییریافته همراه Rust Manager در Release منتشر می‌شود. باینری اصلی upstream قابلیت Auto ندارد. Anti-Replay Window مستقل و Forward Secrecy هنوز در این نسخه پیاده‌سازی نشده‌اند؛ همچنین رمزگذاری به‌تنهایی غیرقابل‌شناسایی‌شدن ICMP را تضمین نمی‌کند.

## Adaptive Performance — کاملاً خودکار

هسته Go سمت ایران بدون اجرای پردازش مدیریتی جداگانه، با استفاده از Pingهای موجود ICMP، RTT، Jitter و پاسخ‌ندادن به Pingها را اندازه می‌گیرد. در نتیجه **هیچ پروب اضافه‌ای صرفاً برای تنظیم عملکرد** ارسال نمی‌شود. یک کنترلر با میانگین هموار و تشخیص خرابی/بازگشت تدریجی، پارامترهای شروع **اتصال‌های TCP جدید** را برحسب کیفیت فعلی تنظیم می‌کند:

- زمان Retransmission بر اساس RTT هموارشده + نوسان تأخیر، در محدوده محافظه‌کارانه
- محدودکردن پنجره ارسال اتصال‌های جدید در شرایط ازدحام/پاسخ‌ندادن و بازگشت تدریجی بعد از بهبود
- حفظ کنترل ازدحام پیش‌فرض `BB` هسته Go که برای اتصال‌های TCP **در حال اجرا** به‌طور داخلی تنظیم می‌شود
- حفظ مقادیر سفارشی TCP، اگر کیفیت مسیر هنوز نمونه کافی برای تنظیم نداشته باشد
- **بدون** Restart اجباری هسته Go، بدون تغییر پنجره نشست برقرار و بدون جابه‌جایی بین چند سرور

در منوی `pingtunnel` گزینه `14 — Adaptive Performance status` وضعیت RTT، Jitter، برآورد از دست‌رفتن پاسخ Ping، وضعیت مسیر و تنظیمات **اتصال TCP بعدی** را نشان می‌دهد. همچنین می‌توان از فرمان `pingtunnel performance` استفاده کرد. گزارش بی‌کلید در فایل خصوصی `/run/pingtunnel-performance.json` قرار می‌گیرد.

**محدودیت مهم:** Adaptive Performance فعلاً فقط تنظیمات شروع نشست‌های TCP جدید را تغییر می‌دهد و از کنترل ازدحام BB موجود برای نشست‌های زنده استفاده می‌کند. این قابلیت هنوز **اصلاح زنده Retransmission در TCP برقرار، تشخیص دقیق Packet Loss داده یا تنظیم سرعت UDP** نیست. اگر ICMP به‌طور کامل مسدود شود، کنترلر نمی‌تواند با تنظیم پارامترها اتصال را برقرار کند. نتایج واقعی باید روی VPS ایران و خارج اندازه‌گیری شوند.

تنظیمات منو بعد از ذخیره، به‌صورت خودکار با systemd هماهنگ و اعمال می‌شوند. نیازی نیست `service-install` و `restart` را جداگانه اجرا کنی.

## ارتقا از نسخه‌های دارای HA

نصب‌کننده 2.4 به‌صورت خودکار بخش قدیمی `ha` را از تنظیمات حذف می‌کند و با حفظ نقش Client/Server، **آدرس سرور اصلی، کلید، مقصد، پورت، حالت TCP/UDP و autostart** سرویس تک‌مسیره را راه‌اندازی می‌کند. فایل تنظیمات قدیمی قبل از مهاجرت در این مسیر نگهداری می‌شود:

```text
/opt/pingtunnel/conf/config.json.before-single-route.bak
```

نصب‌کننده همچنین در صورت شکست ارتقا می‌کوشد تنظیمات و سرویس قبلی را بازگرداند. فایل‌های اجراکننده HA از کد اصلی مخزن حذف شده‌اند و سرویس systemd جدید مستقیماً هسته Go را اجرا می‌کند. **ارتقای سرویس فعال ممکن است یک وقفهٔ کوتاه ایجاد کند.** پیش از نصب روی سرور عملیاتی، بهتر است جداگانه از کانفیگ بکاپ بگیری.

## وضعیت سرویس و عیب‌یابی

```bash
pingtunnel
sudo systemctl status pingtunnel.service --no-pager
sudo journalctl -u pingtunnel.service -n 100 --no-pager
sudo systemctl show pingtunnel.service -p MainPID -p MemoryCurrent -p NRestarts
```

فایل تنظیمات: `/opt/pingtunnel/conf/config.json` (مجوز 0600). هسته Go در `/opt/pingtunnel/bin/pingtunnel` و فرمان مدیریتی در `/usr/local/bin/pingtunnel` نصب می‌شوند.
